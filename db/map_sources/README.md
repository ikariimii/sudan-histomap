# Map sources and border transitions (for the Web Lead)

Generated by `python3 db/map_sources/build_map_sources.py`. It reads only existing files and creates no geometry.

## db/map_sources.json
`eras.<era_id>.shapes[]` has one row per feature in `db/extents/<era_id>.geojson` and `db/trade_routes/<era_id>.geojson`. Each row gives:
- `zone_type`, `cites[{id,pages}]`, `badges` and `confidence`.
- `base_source`: the base-source types named in the feature's own provenance. It is null when none is named, with `base_source_null_reason`.
- `overlay_maps`: the maps in db/border_overlay_maps.json for this draft.
- `overlay_mean_error_km`: null in every row so far, with `overlay_null_reason`. No shape was traced from a georeferenced map, and that file has no mean-error field.

The full schema is in `meta.schema`.

## db/border_transitions.json
`transitions[]` lists each pair of consecutive eras in the same stream (data/periods.json, sorted by start and then end):
- `pairs[]`:
  - `from` / `to`: era_id, feature_id (`<era>#<index>` when there is no id), feature_index, zone and cites.
  - `mode`:
    - `hold`: the geometry is identical, so draw it unchanged.
    - `morph`: IoU of 0.3 or more, so tween between the two shapes.
    - `cross_fade`: the shapes overlap with an IoU below 0.3.
  - `shared_edge_km_approx` and `changed_sides` (bbox side deltas per N/S/E/W). These are display aids, not sourced limits.
- `fade_out` / `fade_in`: polygons with no overlapping partner in the other era.

Show the cites for both sides in the hover. Contested areas are points and are never paired.
